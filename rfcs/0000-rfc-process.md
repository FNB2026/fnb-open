# RFC Process

## What is an RFC?

An RFC (Request For Comments) is a structured proposal for a significant change to the FNB protocol, architecture, or governance.

## When to Create an RFC

Create an RFC for:
- New or modified protocol objects
- Changes to core domain model
- Permission model changes
- Data sovereignty impact
- AI boundary changes
- Governance or licensing changes
- Any change that breaks backward compatibility

## RFC Lifecycle

```
Draft → Discussion → Revision → Accepted / Rejected / Superseded
```

1. **Draft** — Create an RFC using the template, submit as a PR
2. **Discussion** — Minimum 7 days for public comment
3. **Revision** — Incorporate feedback, update the RFC
4. **Decision** — Maintainers vote; Steward has final say

## RFC Numbering

RFCs are numbered sequentially: `RFC-0001`, `RFC-0002`, etc.
